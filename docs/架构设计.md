# 架构设计

本文说明星星脱敏的分层、数据流、坐标体系与关键取舍，方便二次开发。

## 1. 目标与约束

| 目标 | 落地方式 |
| --- | --- |
| 纯本地离线 | 不引入任何 HTTP 客户端；OCR/pdfium 均为本地文件 |
| 低耦合、可替换 | 解析/识别/脱敏/导出四层只依赖 `models` 中的数据结构 |
| 高召回 + 可复核 | 自动识别给出置信度，人工标记优先级最高，导出以“启用”的标记为准 |
| 大文档流畅 | 字符级下标 + 单遍扫描 + 后台线程（`spawn_blocking`） |
| 保留排版 | Word 走 XML 定点改写；PDF 走“渲染 + 涂黑”，不重建版式 |
| 可审计 | 每次导出生成含 SHA-256 的 JSON/TXT 留痕 |

## 2. 分层与依赖方向

```text
              ┌──────────────────────────────┐
   前端 TS ──▶│ commands（Tauri 命令层）      │
              └──────────────┬───────────────┘
                             │ 只通过 models 中的 DTO 交互
      ┌──────────────────────┼───────────────────────┐
      ▼                      ▼                       ▼
┌───────────┐        ┌──────────────┐        ┌──────────────┐
│ parser    │        │ detect       │        │ export       │
│ 解析层     │        │ 识别层        │        │ 导出层        │
└─────┬─────┘        └──────┬───────┘        └──────┬───────┘
      │                     │                       │
      │ ParseOptions        │ Rule[]                │ ParsedDoc + Finding[]
      ▼                     ▼                       ▼
              ┌──────────────────────────────┐
              │ models（ParsedDoc / Finding） │
              └──────────────┬───────────────┘
                             ▼
                    ┌─────────────────┐
                    │ redact（脱敏）   │
                    └─────────────────┘
```

- **不允许反向依赖**：parser 不知道 detect，detect 不知道 export；export 只接收数据。
- `config` 只负责持久化，不参与业务判断。
- `state` 持有文档会话与 OCR 引擎缓存，是命令层的“内存数据库”。

## 3. 坐标体系（全项目唯一真相）

一份文档在内存中只有一份 `ParsedDoc::text`（全文 `String`）和一套**字符下标**
（Unicode 标量，不是字节）。所有命中、高亮、脱敏都围绕它进行。

```rust
ParsedDoc {
    text: String,             // 全文，块/页之间以 '\n' 连接
    blocks: Vec<TextBlock>,   // 段落（docx 用于定点改写）
    pages: Vec<PageRange>,    // 每页在全文中的 [start, end)
    page_count: usize,
    layouts: Vec<PageLayout>, // PDF 字符框 / OCR 行框（导出 PDF 用）
}
```

为什么用字符下标而不是字节：

- 前端 JS 用码点/UTF-16 处理文本，字符下标最接近；
- 中文一个字 3 字节，用字节会让“第 42 个字”难以表达；
- 正则库返回字节偏移，识别层在入口处用 `CharIndex`（字符起始字节的二分查找）一次性换算。

`CharIndex`：

```rust
starts[i] = 第 i 个字符的起始字节；末尾再 push text.len()
index_of(byte) = starts.binary_search(byte) // O(log n)
```

PDF 的字符坐标（`PageLayout::chars`）与页文本按字符一一对应，导出时用同一套下标定位。

## 4. 解析层

### 4.1 PDF

1. `pdfium-render` 加载动态库（`Pdfium::bind_to_library`），逐页 `page.text().chars()`；
2. 每个字符取 `tight_bounds()`，转换为「左上角原点」的点坐标；
3. 依据显式换行字符 + 「回到行首且明显下移」补换行（避免把同一行切碎）；
4. 每页有效字符数 < 20 × 页数 → 判定扫描件；整体有文字但个别页无文字层时，
   按“混合型 PDF”只 OCR 空白页；
5. 扫描件逐页渲染（`PdfRenderConfig::scale_page_by_factor(dpi/72)`）→ OCR 引擎；
6. 无 pdfium 时退化为 `lopdf::extract_text_chunks`（只有文本，无坐标）。

PDF 文字层顺序在少数文件中与视觉顺序不一致，这是格式本身的限制，已在 README 说明。

### 4.2 Word

`docx` 本质是 zip：

1. 读取 `word/document.xml`；
2. `roxmltree` 遍历所有 `<w:p>`，收集其下 `<w:t>` 的**字节区间**与文本；
3. 段落文本按文档顺序拼接为全文，空段落也保留（保证下标与导出时的段落一一对应）；
4. 识别到段落样式 `Heading*` / `标题*` 时标记为标题块。

导出时重新解析同一份 XML，按段落下标找到对应块，用脱敏结果替换第一个 `<w:t>`，
其余 `<w:t>` 清空。这样 `pPr`（对齐、缩进、编号）、表格、图片、页眉页脚全部保留。

### 4.3 TXT

BOM 优先（UTF-8/UTF-16），其次 UTF-8 合法性，最后按 GB18030 解码。按行切块，
按段落边界做虚拟分页（约 3000 字/页）。

### 4.4 RTF / HTML

- RTF：手写轻量解析器，跳过字体表/样式表/图片等目标组，支持 `\uN`、`\'hh`（GBK/GB18030）
  和 `\par`/`\page`，只取正文；
- HTML：去 `<script>/<style>/注释`，按块级标签补换行，解码常见实体；不访问外部资源。
- 两者都按段落做虚拟分页，导出时生成新 Word/TXT。

### 4.5 OFD

OFD 是 zip + XML：读取 `Doc_*/Pages/Page_*/Content.xml`，把 `<ofd:TextCode>` 的
`X`/`Y` 坐标按行（Y 容差 0.5）重组，行内按 X 排序。扫描图片型 OFD 没有 TextCode，
会提示先转 PDF/图片再 OCR；不保留原版式，只能导出 TXT/Word。

### 4.6 旧版 Word / WPS

`.doc` 优先走 `doc_binary.rs` 的纯 Rust 解析：用 `cfb` 读取 OLE 复合文档，
解析 FIB、CLX/piece table，压缩片段按 GB18030、未压缩片段按 UTF-16LE 还原正文。
解析失败（Word 6/95、加密、结构异常）才回退本机 LibreOffice 无头转换；
macOS 的 `.doc` 还可用系统 `textutil`。转换超时 180 秒，临时目录解析后立即删除。
`.wps` 先识别 OOXML，二进制版同样先试原生解析；`.docm` 导出时重新生成 docx，剥离 VBA 宏。

## 5. 识别层

```text
规则（regex/keyword/ner）
      │ 候选 Candidate { start, end, confidence, category, ... }
可选：本地 NER 小模型（仅开关打开时）
      │ 补充 Candidate（source=Model，priority=40）
      ▼
二次校验（身份证校验位 / Luhn / USCC）→ 微调置信度
      ▼
阈值过滤（丢弃 < settings.threshold）
      ▼
冲突消解（起点 → 长度 → 置信度 → 优先级；贪心不重叠）
      ▼
同名传播（已确认的姓名/律所，在全文其他位置补标）
      ▼
Finding[]（带 enabled / strategy，供复核）
```

关键点：

- **一次编译、多次复用**：`DetectEngine::build` 编译全部正则，`detect` 只做扫描。
- **可选增强识别**：`detect/model_ner.rs` 内置 `hfl/minirbt-h288` 微调的 12 MB 中文 NER
  （PER/ORG/LOC），先按 BERT 中文分词切成 token，再以 510 token 分块（重叠 48）用 `tract`
  推理，BIO 解码后映射为姓名/单位/律所/法院/住址。模型结果优先级 40，低于规则，
  只补漏不抢已有命中；默认关闭。
- **PDF 跨行处理**：PDF 的折行不是语义换行，识别前去掉 `\n`，同时建立
  `去换行下标 → 原文下标` 映射；命中后回写原文坐标，因此高亮/脱敏不会偏移。
  Word/TXT 保留换行，避免跨段误匹配。
- **人名识别**（`ner.rs`）：姓氏表（含复姓）+ 27 个上下文线索（原告、被告、代理人、
  法定代表人…）+ 连接词边界（诉/与/和/系/等）。例如「原告张三诉被告李四」能正确切出
  「张三」「李四」，而「原告通过银行」不会把「通过」当人名。
- **校验器只微调不丢弃**：文书里的号码常有录入错误，直接丢弃会造成漏脱敏。
- **同名传播**：姓名在文书里往往反复出现，只标第一次等于没脱敏；传播时要求前后不紧贴
  汉字/字母数字，避免「张三」命中「张三丰」。

## 6. 脱敏层

纯函数：`redact_text(text, findings) -> RedactionOutput { text, segments, by_category }`。

- 仅处理 `enabled = true` 的命中；
- 按起点排序，重叠区间跳过（取先出现者）；
- 三种策略：Mask（保留前后 N 位 + 掩码字符）、Placeholder（`{type}` / `{index}`）、Delete；
- 命中跨度可能包含 PDF 折行符，生成替换文本时先剔除 `\n`/`\r`，避免掩码残留半截行；
- `segments` 记录每处变更，供前端对照视图与导出日志使用。

## 7. 导出层

### 7.1 TXT

UTF-8 + BOM。

### 7.2 DOCX

- 源文件是 docx：`export_preserving`，见 4.2；
- 其他来源：`docx-rs` 逐段生成新文档。

### 7.3 脱敏 PDF

1. 打开一次 pdfium，**逐页渲染 → 涂黑 → 编码 JPEG**，内存中只保留压缩后的页图
   （100 页以上卷宗不会因整本页图同时驻留而 OOM），默认 150 DPI；
2. 用 `PageLayout` 把每处命中换算成矩形：
   - 文字 PDF：字符框按行合并；
   - 扫描件：OCR 行框，按字符占比切出水平范围；
3. 按字高外扩 35% 涂黑（避免字形上下伸出）；
4. JPEG（质量 85）编码，用 `lopdf` 组装为图片型 PDF（每页一个 Image XObject）。

导出前会重新计算源文件 SHA-256，与导入时比对；若文件被替换/修改则中止导出，
避免旧坐标套在新文件上造成漏脱敏。页面数与导入时不一致、或某页缺少坐标但又有命中时，
同样直接失败而不是输出“看似脱敏、实则原样”的页面。

**为什么输出图片型 PDF**：只要保留文字层，就存在被复制、被检索、被逆向提取的风险；
图片化 + 实心遮盖是卷宗对外交付最稳妥的做法。代价是不可检索，README 已说明。

### 7.4 合规日志

`audit.rs` 从 `segments` + `findings` 还原每条记录（页码、原文、替换、方式、置信度、来源），
生成 JSON（结构化管理）与 TXT（打印附卷）。报告头包含源文件 SHA-256、大小、时间、工具版本。

## 8. OCR 层

- `OcrEngine` trait：`is_ready` / `message` / `recognize(&RgbImage)`。
- 默认实现 `PaddleOcr`：纯 Rust 推理（`tract-onnx`），不依赖 Python、不依赖 C++ 运行库。
- 模型：PP-OCR 的 DB 检测 + CRNN/CTC 识别（ONNX，约 13 MB），随仓库与安装包分发；
  加载顺序为「环境变量 → 用户配置目录 → 安装包内置」，任何电脑装好即可离线 OCR。
- 预处理：检测固定 960×960 letterbox；识别固定 48×960、右侧补零。ONNX 输入是动态维度，
  tract 需要显式 `set_input_fact` 才能定图，因此固定尺寸是最稳的方案。
- 后处理：概率图二值化 → 8 邻域连通域 → 面积/周长外扩（DB unclip 近似）→ 同行合并
  → 逐行裁剪识别 → CTC 贪婪解码 + softmax 置信度。
- OCR 文本做全角→半角归一化（`２０２４` → `2024`），长度不变，坐标不偏移。
- 备用实现 `ExternalOcr`：调用本机已有 OCR 命令（`{image}` 占位），全部离线。

## 9. 并发与内存

- Tauri 命令凡是可能耗时的，都 `async fn` + `tauri::async_runtime::spawn_blocking`；
  `AppState` 内部字段是 `Arc<Mutex<…>>`，命令先克隆 `Ctx` 再进后台线程。
- 文档只解析一次，之后所有操作复用 `Arc<ParsedDoc>`。
- OCR 引擎按配置字符串缓存（模型加载/图优化只做一次）。
- 识别阶段临时分配：`Vec<char>`（全文）+ `Vec<usize>`（字节映射），10 万字约 2 MB。

## 10. 失败与降级

| 失败点 | 行为 |
| --- | --- |
| pdfium 缺失 | PDF 退化为 lopdf 文本抽取，扫描件提示无法 OCR，PDF 导出报错但 TXT/Word 正常 |
| OCR 模型缺失 | 扫描件提示安装模型，不影响文字版文档 |
| 单页解析失败 | 记录警告，继续其他页 |
| docx XML 结构异常 | 导出回退为“重新生成 Word”并提示 |
| 单个文件导入失败 | 计入 errors，整批继续 |
| 导出某格式失败 | 警告返回前端，其他格式照常产出 |

## 11. 扩展点

- **新增识别类型**：在 `detect/builtin_rules.rs` 加一条 `Rule`，或直接在界面新增（无需改代码）。
- **新增 OCR 引擎**：实现 `OcrEngine`，在 `parser/ocr/mod.rs::build_engine` 注册。
- **新增导出格式**：在 `export/` 加模块，在 `export::export` 增加分支。
- **更好的 NER**：增强识别已经接入本地 ONNX 序列标注模型；还可替换 `detect/ner.rs` 的规则实现，
  保持 `NameHit { start, end, name, category, confidence }` 接口不变即可。

## 12. 安全边界

- 无网络代码；`api.ts` 集中列出全部后端调用，便于审计。
- 文件写入仅两处：应用配置目录、用户选择的导出目录。
- 原始文件只读，不落盘任何中间副本（OCR 临时图片使用系统临时目录，识别后立即删除）。
- 日志含原文片段是“留痕”的必要设计，导出目录应视同卷宗材料管理。
